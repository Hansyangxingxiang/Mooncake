架构图中的虚线表示控制、引用或定位关系，具体含义以边上标注为准；粗线用于强调数据搬运。其他流程图中的线条用于步骤连接，不表达物理部署。

既有文本调用链保留函数名和历史行号，供源码检索；新增图示解释角色、约束与状态变化。代码块含 `...` 或只展示局部分支时属于节选，不应直接作为可编译示例。

## 证据与验证边界

本轮整理完成的是文档结构、图示及结论边界审阅，未完成历史版本逐行源码审计。`7197358` 在当前检出中可解析（`v0.3.13.post1` 指向 `719735896c86b56fabec6cf3e825fb2ea640597a`），但当前 main 的编译或测试结果仍不能代替历史版本的验证。各篇“验证与结论”中的测试文件是查证入口，列出文件不表示其中用例已执行或已证明该篇全部结论。

后续复核按以下粒度记录，避免只罗列文件名：

| 待证明的结论 | 应提供的证据 | 状态记录 |
|---|---|---|
| 未完成副本不能被普通 Get 选中 | 固定版本的可读判断、并发写读测试用例 | 静态核对与运行结果分别记录 |
| 过期 lease 的读取结果被拒绝 | lease 授予与完成检查、受控到期用例 | 区分正常删除、force 与节点故障 |
| 部分提交后可安全释放 batch | 后端收尾与释放条件、部分提交失败用例 | 区分错误已报告与设备操作已停止 |
| 下沉副本可在重启后恢复 | 文件及目录同步、Init 校验、故障注入结果 | 区分进程重启与掉电持久性 |
| vLLM 加载失败后正确恢复 | 固定 vLLM commit、connector 与 scheduler 调用链、端到端用例 | 目前外部实现待核实 |

源码引用应逐步采用“固定完整 commit 的永久链接 + 函数或类型名 + 必要行号”。当前各篇保留原 tag 链接基座，不伪造未复核的完整 commit 或行号。vLLM 需要独立记录其版本；Mooncake Python 接口存在，不足以证明外部 connector 使用该接口。
